# 产品设计主入口

当前目标：输入目标 → 澄清需求 → 生成设计 → 审查一致性 → 用户确认。

- 新项目直接打开设计工作台。「打开设计助手」选择当前项目并准备设计请求；只有用户选择模型并发送后才运行，不会静默开工。
- 请求使用现有应用设计工具生成可审阅资料。用户在设计文档中确认和提出修改。导航步骤不伪造进行中、已完成或审批状态。
- 页面内助手不提供自主代码执行或命令/文件授权按钮。服务端负责强制设计工具边界，不能仅依赖这段说明或模型提示词。
- 外部 harness 的开发门禁、计划、证据和编排页面保持有效，并有独立的「外部开发 / 工单」入口。外部 harness 执行代码任务，必须提交进展、问题、变更和验证工单；内置设计助手不代替外部开发，不把开发动作改名冒充设计。
- 工作流加载失败可重试；没有下一步不等于已完成。已有版本、审计和数据不会为了简化界面而删除。
- API Key 与 ChatGPT 账户登录是不同认证方式。只有显式点击登录才开始官方流程；账户和模型状态来自后端。目录列出某模型不保证套餐权限或剩余额度允许使用。目前订阅通道仅开放登录/状态/模型目录，Codex 设计执行保持关闭，直到可验证强制禁用代码执行与源码写入；不会自动回退到独立计费的 API Key。

## 验证范围

单元测试覆盖创建/重复提交/失败重试、设计请求准备、默认导航、历史门禁不提供执行入口、账户登录/取消/中断/错误/模型来源和两种认证模式。

`tests/e2e/project-main-flow.spec.ts` 是完全隔离 API fixtures 的浏览器回归，不接触真实项目或登录。当前环境 Chromium 的 socket 权限受限，云浏览器拒绝本地地址，因此真实浏览器与截图验收仍未完成，不能用单元测试替代。

## 需求影响误分类的正式更正

项目设计工作台和节点详情读取服务端的 `design-change-recoveries` 候选，不从本地文案推测可恢复状态。对仍在返工、原判定不影响需求的变更，用户可提交带原变更 ID 的更正意图；理由与需求/验收变化必须填写。

提交只进入独立复核工单，不等于批准，不把根计划改成已验收，也不直接恢复施工。批准后的需求修订与恢复由服务端执行并保留原记录；过期快照须刷新后再提交。这个入口解决的是需求影响误分类的更正路径，尚不代表已实现一般依赖死锁处理、完整需求覆盖检查或任意工单自动恢复。
