## 目标与边界

主 Agent 领取并负责一个任务的完整交付，编码 Agent 制定施工计划并施工，审批 Agent 独立审核；所有常规批准、返工决策和闭环由主 Agent 完成。关闭当前任务后自动领取下一任务。

用户追加明确要求：本协议对所有接入 ProductDesign 的外部 Agent、全部项目统一生效，不限当前 Codex 会话、特定模型、Agent 名字或 PRODUCTDESIGN 项目。本文关联 PRODUCTDESIGN 的平台交付节点，表示在此开发平台能力，不表示只在此项目执行该协议。

## 全局接入契约

1. MCP initialize.instructions、工具说明、任务包和 REST 接入说明必须引用同一版本的角色与交付协议。
2. 外部 Agent 参与交付前必须获取当前协议并声明可承担的角色。服务端校验授权和能力，不能把声明本身当作可信权限；版本不兼容时拒绝受控写并返回升级说明。
3. 外部主 Agent 负责调度编码和审批 Agent；接入为编码或审批角色的 Agent 只能领取相应阶段工单，不能升级为主 Agent。客户端无调度能力时明确报告能力缺口，不伪称能够自动启动其他 Agent。
4. 所有项目使用同一状态迁移和授权校验。MCP、REST 及外部 Agent 可触达的其他写入口都必须经过相同业务门禁，不能因客户端名字、模型、来源字段或项目不同而跳过。
5. 接入告知与执行约束分开验收：提示词告知完整流程，服务端强制阻止越权、跳步、自审、无证据闭环。平台不能强迫任意外部客户端持续运行；客户端必须实际实现调度循环，才能宣称支持自动连续交付。
6. 现有活跃租约不能静默套用新状态语义。协议升级需定义旧租约结束或失效、修订迁移和重新领取步骤，保留历史记录与恢复入口；不把旧任务批量标为已验收。

保留项目简报、需求、详细设计、数据库绑定、测试证据和独立身份等门禁。编码 Agent 的施工计划建立在已批准需求和详细设计上；本变更不赋予其自行修改需求或批准自己的计划的权限。主 Agent 不编写被审产物，审批 Agent 不修改被审代码。真实资金、不可逆删除、对外发布、权限扩张与认证策略变更仍需人工授权。

## 交付流程

1. 主 Agent 原子领取一个待交付任务，并在持久状态中保留负责关系。
2. 主 Agent 派发计划准备阶段给编码 Agent。此时只能提交施工步骤、影响范围、依赖、测试命令、风险和完成条件，不能开工。
3. 主 Agent 审核固定版本的施工计划。拒绝需写明原因并返回计划准备；批准后进入可施工状态。
4. 编码 Agent 持有施工租约，在隔离工作目录施工，提交实现修订、测试结果和证据。
5. 主 Agent 调用不同生产身份的审批 Agent，只读审核固定实现修订与证据。
6. 审批 Agent 提交通过或失败报告，两种结果都进入主 Agent 评估阶段，不直接闭环或开返工。
7. 主 Agent 评估：失败或证据不足时发出返工决定；编码 Agent 修复并提交新修订，再由审批 Agent 复审。审核失败不得被主 Agent 直接标为验收通过；对报告有异议时要求重新审核并保留原报告。
8. 审核通过、证据完整且所有前置门禁满足后，主 Agent 用独立批准工单完成验收并关闭任务。
9. 确认服务端闭环成功、释放本轮资源后，主 Agent 重新读取工作流，使用新的领取幂等键领取下一任务。没有可领任务则等待；不能把队列为空解释为项目完成。

## 数据与授权

沿用计划、不可变文档修订、证据、租约与审计记录作为真源，不建立脱离画布交付节点的第二套完成状态。

详细实现需明确主 Agent 对整项任务的负责关系与子阶段租约的关系：不得把主租约令牌交给子 Agent；每个执行进程使用唯一 workerId，每阶段使用独立工单、正确角色和资源范围。主 Agent 负责关系不能持有与子阶段冲突的独占施工锁。

施工计划准备与施工必须区分授权阶段，即使由同一个编码 Agent 完成也不能提前开放源码写入。审批人与编码生产者必须不同；主 Agent 批准身份必须与生产、独立审核身份分开。用结构化角色和服务端授权判断，不能按显示名或 ID 字符串猜测角色。

主 Agent 负责关系、计划准备和报告评估如需新增持久字段或状态，先登记数据库模型及节点绑定，再开发与迁移。旧计划及证据不自动改成已通过，旧人工验收待办需要在新协议下验证角色和当前证据后才能转换。

## 失败、并发与恢复

- 领取必须原子化；重复请求复用同一次调用的幂等键，新任务使用新键。
- 租约失效、修订漂移、身份不匹配或资源冲突立即停止该阶段写入，重新读取服务端状态。
- 主 Agent 重启后恢复已负责任务及当前阶段，不能凭对话记忆重新领一份或重复验收。
- 审核报告绑定本次实现修订；旧报告不得批准新代码。返工保留原报告、新修订与替代证据关联。
- 验收写入响应不明确时先读回状态，不盲目重试，不先领取下一任务。
- 当前任务等待人工或外部依赖时记录原因和解除条件；不要持续重试同一失败操作。
- 等待时采用退避，只在有效执行租约内发送心跳，不创建未经授权的外部进程。

## 当前阻塞与解除条件

### 2026-09-06：主 Agent 发起设计变更

用户明确批准将常规设计变更开放给工作中的主 Agent。实现沿用现有独立 `approver` 工单，不新增身份角色或数据库表：MCP 将 `request_design_change` 从一律人工高风险调整为受控写；MCP/REST 共用领域权限校验，要求完整且匹配的工单 ID、租约令牌、任务键/修订、workerId、agentId、approver 角色及目标节点范围。普通 Designer/Builder/Auditor 不可调用此权限。

现有设计变更只创建待评审修订、冻结施工并保留历史，不执行资金、部署、权限配置、认证配置或不可逆删除；这些实际高风险工具保持人工门禁。变更不能直接批准新设计或恢复施工。

同一变更会使自己的旧批准租约失效，因此幂等恢复必须绑定原主体与工单，并仅允许读回这次已提交变更的结果，不能把失效租约用于第二次变更。拒绝错角色、伪造主体、过期租约、跨项目/节点及变更载荷漂移；保留原有画布版本检查、证据与租约原子失效。测试覆盖外部 MCP、REST、领域门禁和失败回滚。

### 新发现：领取返回错误但租约已提交

用户报告 `claim_next_agent_task` 返回错误，界面仍显示 Main Agent 已领取审批工单。代码检查确认存在对应失败路径，但本次具体项目、错误码和工单尚待定位：

- `src/mcp/index.ts` 的领取处理先调用 `claimAgentTask`，再调用 `buildAgentTaskPackage` 并序列化返回；前者在 `src/server/agentTaskLeases.ts` 内独立事务提交租约和幂等缓存，后者失败不回滚前者。
- 任务包阶段仍可能因工作目录、任务选择、角色配置、角色蓝图或受派身份检查失败而抛错。因此普通错误返回不能证明领取没有生效。
- MCP 领取入口在省略 sessionId/runId 时每次生成随机值，而领取幂等摘要包括这两个字段；相同原始请求重试可能产生 IDEMPOTENCY_CONFLICT。REST 任务包入口也有先领取后构建及随机补值路径，应一并验证。
- 本轮读取 PRODUCTDESIGN 全部 61 条租约，未发现活动租约或 approver 租约；不能据此否认其他项目或另一运行实例上的报告。

修复要求：把可失败的任务包构建与响应序列化纳入领取事务边界，失败时回滚本次新建租约、资源占用及幂等结果；对已提交但传输失败的结果，提供同主体、同原始请求的幂等恢复。随机默认值只能在首次成功处理时生成并持久化，不能影响原始请求摘要。已到期、失效或完成的旧租约重试应返回明确状态，不能当作新的可执行授权。恢复入口不得向其他主体泄露令牌。

增加最小验收：任务包构建失败无新增活动租约；序列化失败无残留占用；省略可选标识重复调用返回同一有效工单；模拟响应丢失后可恢复；更换载荷报幂等冲突；并发领取恰好一个成功；MCP 与 REST 行为一致。实际传输无法与数据库提交形成单一事务，不能承诺所有网络错误都等价于未领取。

本缺陷修复进展：用户单独指示“修复”后，在既有原子领取和幂等契约下领取施工工单 `46fb38df-968a-4e9a-8942-a880108cfe3b`。新增共用 `src/server/claimTaskPackage.ts`，将领取、任务包构建和 JSON 序列化纳入同一事务；三个入口使用稳定缺省标识；领取缓存重放读取当前租约并拒绝已结束授权。四个测试文件共 62 项通过，`npm run build`（含类型检查）通过，证据 `a651e278-a3fb-4b1a-94e0-53e4bc81b4d4`。此局部缺陷修复不代表全局主 Agent 编排变更已实现或整个 v2.3 计划已完成。

### 开工前设计缺口入口（2026-09-08）

适用现有节点“外部 Agent 编排与可信交付链”：Builder 对 approved/in_progress 计划使用 `report_design_gap`，携带完整当前租约上下文、稳定幂等键和具体 error（缺口及解除条件）。控制面复用租约历史记录报告，原子释放施工租约、资源锁及工作区占用，生成同节点独立 `request_design_change` approval 工单，不计入证据修复失败次数。

主 Agent 核对影响范围后复用设计变更：创建待评审修订、撤销旧证据和工单、转 Designer 提交，再经独立设计审计及主 Agent 批准恢复施工。报告误判时可使用 `dismiss_design_gap` 写明原因，关闭审批租约并生成新施工任务修订；不得复用旧施工租约。冻结文档出现新修订、丢失或不再批准时，控制面自动生成缺口并拒绝开工/完成；修订漂移不可按误报驳回。未登记的本地文件不会被猜测为平台设计基线，须由 Builder 报告。

MCP 与 REST 共用租约控制；报告/驳回均核验工单、主体、角色、范围和当前修订。保留独立生产身份、证据修复 assessment、跨节点依赖闭包及 human-only 高风险执行边界。回归覆盖报告重放、伪造上下文拒绝、旧施工拦截、误报恢复、新修订检测、外部 MCP 以及设计变更后提交→审计→批准→新施工队列。

### 同一设计缺口的跨节点审批组（2026-09-08）

沿用“外部 Agent 编排与可信交付链”节点的独立范围审批租约：同一缺口、完整影响范围和任务修订由服务端编排队列确定，领取入口在一个事务中创建全部租约、资源锁、工作区预留及幂等结果。每组占一个项目/Approver/Worker 池槽位；普通任务仍逐项计数，不再豁免容量检查。任一成员失败或响应序列化失败，整组回滚。

返回 approvalGroupId 与 scopeApprovals；同一 Worker 执行同一组，成员保留各自节点范围、任务键、修订及令牌，不得用于普通批准或生产动作。主 Agent 设计变更提交必须携带全部成员且范围/修订仍为当前值；保留生产身份隔离与跨节点闭包校验。任一成员续租或释放作用于整组，任何成员到期使整组到期并回收资源；发生范围/修订漂移时拒绝继续执行，允许释放后重新领取。既有未分组租约不被自动合并或接管。

验收：7 节点占一个槽位；容量 2 时两个组成功、第三组拒绝；插入中途故障无残留；幂等返回完整范围租约；旧修订、自审批、普通审批动作均拒绝；整组续租、释放和过期正确。
